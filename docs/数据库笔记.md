## 1. 数据模型：库 → 表 → 行 → 列

```
MySQL 服务端（进程，监听 3306）
  └── 数据库 imgsvc              一个"库"，装一组相关的表
```

## 2. 你的表：每一列为什么这么设计

```sql
CREATE TABLE infer_log (
  id          bigint unsigned NOT NULL AUTO_INCREMENT,
  image_name  varchar(255)    NOT NULL,
  image_hash  char(64)        NOT NULL,
  result_json json            DEFAULT NULL,
  cost_ms     int unsigned    NOT NULL DEFAULT 0,
  created_at  timestamp       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_created_at (created_at),
  KEY idx_image_hash (image_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 列 | 类型 | 为什么 |
|---|---|---|
| `id` | `bigint unsigned` + `AUTO_INCREMENT` | 主键。插入时不用给值，数据库自动 1、2、3… |
| `image_name` | `varchar(255)` | **变长**字符串。文件名长短不一 |
| `image_hash` | `char(64)` | **定长**。SHA-256 永远是 64 个十六进制字符 |
| `result_json` | `json` | MySQL 5.7+ 原生 JSON 类型，会校验格式 |
| `cost_ms` | `int unsigned` | 耗时（毫秒）。unsigned = 不能为负 |
| `created_at` | `timestamp` + `DEFAULT CURRENT_TIMESTAMP` | 插入时自动填当前时间 |

### char vs varchar（面试常问）

| 类型 | 占用 | 适用 |
|---|---|---|
| `char(N)` | **固定 N 字节**（不足补空格） | 长度完全固定的数据：SHA-256、MD5、身份证号 |
| `varchar(N)` | **按实际长度**（+1~2 字节记录长度） | 长度不定的数据：文件名、用户名 |

`image_hash` 永远是 64 位 → `char(64)` 正好；用 `varchar` 会多存长度信息。
`image_name` 可能是 `a.jpg`（5 字符）也可能是长名字 → `varchar` 省空间。

## 3. 主键与索引

### 主键（PRIMARY KEY）

- 唯一标识一行，不能重复、不能空
- 一张表只有一个主键
- 查询走主键最快（B+ 树，O(log n)）

**为什么不用 `image_name` 当主键？** 两张不同的图可能同名（`IMG_001.jpg`），主键必须唯一。

### 索引（INDEX / KEY）

| 索引 | 建在 | 用途 |
|---|---|---|
| `PRIMARY` | `id` | 主键自带 |
| `idx_created_at` | `created_at` | 「查最近 7 天」这类按时间的查询 |
| `idx_image_hash` | `image_hash` | 「这张图算过没有」这类去重查询 |

**索引 = 书的目录。**

- 没有索引：**全表扫描**，从第 1 行读到最后一行
- 有索引：直接定位到行

验证（`EXPLAIN` 看 `key` 和 `rows` 两列）：

```sql
EXPLAIN SELECT * FROM infer_log WHERE image_hash='abc';
--  type: ref   key: idx_image_hash   rows: 1   Extra: Using index condition
```

`key` 有值 = 走了索引；`type=ALL` = 全表扫描。

**★ 索引不是越多越好**：每次 INSERT 都要同步更新所有索引 → 写入变慢、占磁盘。
只给「经常用来查询的列」建索引。

## 4. SQL 五类语句

### ① CREATE —— 建库建表（一次性）

```sql
CREATE DATABASE imgsvc CHARACTER SET utf8mb4;
CREATE TABLE practice (
  id    INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  name  VARCHAR(50)  NOT NULL,
  score INT          NOT NULL DEFAULT 0
);
```

### ② INSERT —— 写入

```sql
INSERT INTO infer_log (image_name, image_hash, result_json, cost_ms)
VALUES ('消防栓.jpg', '1874bfff…', '{"width":1245}', 291);
```

**`id` 和 `created_at` 不用给**：一个自增，一个自动填时间。

字段名和值的顺序必须一一对应；字符串用单引号，数字不加引号。

### ③ SELECT —— 查询（最常用）

```sql
SELECT id, image_name, cost_ms          -- 要哪些列（* = 全部）
FROM infer_log                          -- 从哪张表
WHERE cost_ms > 250                     -- 条件（可选）
ORDER BY id DESC                        -- 排序：DESC 降序 / ASC 升序（默认 ASC）
LIMIT 20;                               -- 只要 20 条（可选但强烈建议）
```

**`ORDER BY id DESC LIMIT 20` = 最新的 20 条。**

**★ 一定要带 `LIMIT`**：表里有 100 万行时，`SELECT *` 会把 100 万行全读进内存。

**统计函数：**

```sql
SELECT COUNT(*) AS 总条数,
       AVG(cost_ms) AS 平均耗时,
       MAX(cost_ms) AS 最慢,
       MIN(cost_ms) AS 最快
FROM infer_log;
```

### ④ UPDATE —— 修改

```sql
UPDATE infer_log SET cost_ms = 100 WHERE id = 5;
```

**⚠️ 不带 `WHERE` 会改整张表。**

### ⑤ DELETE —— 删除

```sql
DELETE FROM infer_log WHERE id = 5;
```

**⚠️ 不带 `WHERE` 会清空整张表。** 清空整表更快的写法：`TRUNCATE TABLE infer_log;`

## 5. 数据类型速查

| 类型 | 用途 | 例 |
|---|---|---|
| `INT UNSIGNED` | 非负整数 | 耗时毫秒 |
| `BIGINT UNSIGNED` | 大整数（自增 id） | id |
| `CHAR(N)` | 定长字符串 | SHA-256 |
| `VARCHAR(N)` | 变长字符串 | 文件名 |
| `TIMESTAMP` | 时间 | created_at |
| `JSON` | JSON 文档 | result_json |

`NOT NULL` = 不允许空；`DEFAULT x` = 不填时的默认值。

## 6. 工程要点（写代码时必知）

### ① 连接的生命周期

```
mysql_init()          初始化
mysql_real_connect()  连接（host / user / pass / db / port）
  ... 执行很多条 SQL ...
mysql_close()         断开
```

**一条连接可以反复执行 SQL**，不需要每次操作都重连。

### ② 字符集必须显式设置

```cpp
mysql_set_character_set(c, "utf8mb4");
```

不设的话，中文文件名可能变成乱码。你的表、库、服务端都是 utf8mb4，**连接也要对齐**，否则会按错误编码解释字节。

### ③ SQL 注入与转义

**危险写法：**

```cpp
snprintf(sql, ..., "INSERT INTO infer_log (image_name) VALUES ('%s')", user_input);
```

如果 `user_input` 是 `a'); DROP TABLE infer_log; --`，你的表就没了。

**防护：**

```cpp
char esc[1024];
mysql_real_escape_string(c, esc, user_input, strlen(user_input));
```

**更彻底**：预编译语句（`mysql_stmt_prepare` + 参数绑定），SQL 结构和数据彻底分离。

### ④ 连接会超时 → 要重连

MySQL 的 `wait_timeout`（默认 28800 秒 = 8 小时）：连接空闲 8 小时后**服务端主动断开**。

之后再用这条连接会报 `MySQL server has gone away`（错误 2006）。

**防护：**

```cpp
if (mysql_ping(conn) != 0) {
    mysql_real_connect(...);      // 重连
}
```

### ⑤ 执行 SQL 的流程

```cpp
mysql_query(c, sql)              // 执行，返回 0 表示成功
MYSQL_RES* res = mysql_store_result(c);   // 取结果集（只有 SELECT 有）
while ((row = mysql_fetch_row(res))) {    // 逐行取
    row[0], row[1], ...                   // 每列是字符串（可能为 NULL）
}
mysql_free_result(res);                   // ★ 必须释放，否则内存泄漏
```

## 7. 面试问答

**Q: 你的项目为什么用 MySQL？**
A: 要记录每次推理的元数据（文件名、图片指纹、耗时、时间），按时间去重查询。
数据量小、结构固定，用关系型数据库最直接；而且 8.0 支持原生 JSON 列，结果元信息不用拆表。

**Q: 为什么给 `image_hash` 建索引？**
A: 要支持「这张图算过没有」的查询。没索引就全表扫描，100 万行时慢几百倍。

**Q: `char(64)` 和 `varchar(64)` 的区别？**
A: char 定长（固定占 64 字节，不足补空格），varchar 变长（按实际长度 + 长度信息）。
SHA-256 永远 64 位，用 char；文件名长度不定，用 varchar。

**Q: 数据量到 100 万行，你的查询会慢吗？**
A: `/history` 是 `ORDER BY id DESC LIMIT 20`，主键索引倒序扫 20 行，仍然是毫秒级。
但如果是 `ORDER BY cost_ms`（没索引）就会全表排序。

**Q: 怎么防 SQL 注入？**
A: 所有来自客户端的字符串都过 `mysql_real_escape_string`。
更彻底是用预编译语句，把 SQL 结构和数据彻底分开。

**Q: 连接断了怎么办？**
A: MySQL 有 `wait_timeout`（默认 8 小时），空闲会被服务端断开。
我每次操作前用 `mysql_ping` 检查，断了就 `mysql_real_connect` 重连。

**Q: 为什么用 JSON 列存结果？**
A: 结果元信息（宽、高、格式）字段数量可能变化，用 JSON 列避免频繁改表结构；
而且 MySQL 8 的 JSON 列支持用 `->>` 直接取字段。
